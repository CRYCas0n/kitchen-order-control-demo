# Безопасность текущего прототипа

Документ описывает имеющиеся меры и границы, не сертификат безопасности. Публичный сайт предназначен для учебных данных. Настоящие тексты, отправленные подключённым пользователем боту, могут попасть в публичную карточку и историю.

## Секреты и Git

Локальный `.env` содержит admin password, Telegram token и webhook secret; на сервере файл читает systemd/приложение. У текущего deployment `.env` принадлежит root:kitchen-control с режимом 640, корень проекта 750. Приватный SSH-ключ хранится вне проекта на машине администратора, не отправляется архивом приложения.

В Git допускается только `.env.example` с пустыми секретами. Нельзя добавлять рабочую БД, backup, `.env*` кроме example, private keys, реальные Authorization headers, Telegram token, журналы с секретами. [.gitignore](../.gitignore) исключает .env, data, venv, caches, DB/sidecars, key/pem/log/bak/tar.gz, backups и artifacts/local-*.

Gitignore не удаляет уже tracked данные и не чистит старую историю. Перед публикацией:

```bash
git status --short
git diff
git diff --cached
python -m scripts.security_check
```

Сканер проверяет рабочие файлы, index и все reachable Git blobs: сравнивает известные секреты из локального `.env`, ищет шаблоны Telegram/GitHub/AWS/private key, запрещённые пути и проверяет исключение приватных локальных файлов. Результат — artifacts/security-review.json. Если локального `.env` нет, сравнение с его конкретными значениями невозможно; остаются шаблоны. Это не универсальный DLP и не проверка всех возможных видов credential.

При обнаружении настоящего секрета не push: ограничьте доступ, замените/отзовите credential, удалите его из текущего дерева и разберите историю. Одного удаления файла или перевода репозитория в Private недостаточно для ротации секрета. Нельзя переписывать чужую историю force-push без согласованной процедуры.

## Web-доступ и admin

Публичны главная, read API, CSS/JS и учебный static JSON. Нет логина для просмотра заказов. Admin HTML и write endpoint защищены одним Basic Auth: ADMIN_USERNAME/ADMIN_PASSWORD, constant-time сравнение. HTTPS требуется, кроме явного локального исключения ALLOW_LOCAL_HTTP.

POST rework требует X-Requested-With=kitchen-control и проверяет Origin, когда он прислан. CORS не включён. Это не полноценная система web-пользователей: нет отдельных аккаунтов координаторов, MFA, logout, rate limiting, блокировки попыток входа и персонального web-аудита. В истории admin actor_ref всегда «Координатор».

Браузер может кэшировать Basic Auth. Используйте приватное окно, закрывайте его после работы. Не размещайте credentials в URL и скриншотах. При ротации restart обязателен.

## Защита Telegram

Webhook сверяет X-Telegram-Bot-Api-Secret-Token до разбора body, ограничивает размер и тип данных. Только private chat, ожидаемый sender/chat ID, не бот. Update ID ограничен диапазоном SQLite. HTTPS заканчивается на Caddy.

Allowlist — telegram_users.active; действия проверяются по роли и assignee_code, повторно при подтверждении. Координатор не может выполнять задания монтажника только из-за своей роли. Два аккаунта с одним кодом/ролью имеют одинаковый доступ — это необходимо учитывать при назначении.

Nonce защищает старые кнопки нового диалога; TTL — 24 часа. Unique update_id и транзакция защищают от повторной обработки одного update. Outbox dedupe_key защищает повторное создание ответов этого update. Это не защита от компрометации bot token/webhook secret и не ограничение частоты запросов.

Токен хранится только на backend. Отправка использует HTTPS к Telegram API. Не включайте HTTP debug/log request URL с token. Не просите пользователя прислать token/ключ в чат проекта.

## SQLite, сервер и браузер

SQLite и backup находятся вне StaticFiles. Нет endpoint скачивания БД. SQL пользовательских значений параметризован; динамические имена таблиц в служебных scripts берутся из фиксированных списков. Публичный Order скрывает private Telegram IDs, payload и file_id, но не скрывает комментарии и учебные alias.

Uvicorn слушает только bridge-адрес, работает непривилегированно. Proxy headers доверяются только IP Caddy. systemd ограничивает запись каталогом data; admin settings недоступны сервису для изменения. Caddy обслуживает валидный HTTPS. Настройка host firewall и безопасность соседних приложений не управляются этим проектом.

JS экранирует вывод пользовательских строк либо использует textContent. CSP запрещает сторонние источники, inline scripts, object, framing; nosniff и Referrer-Policy дополняют защиту. Swagger/OpenAPI/debug отключены. Это не заменяет отдельное тестирование доступности и безопасность браузера/рабочей машины.

## Логи, backup и screenshots

Логи приложения выводят тип ошибки, ID/статус outbox, не raw Telegram URL или remote error body. Однако сторонние debug-логи и ручные команды могут раскрыть данные: перед передачей просмотрите содержимое. Команда inspect_state показывает реальные IDs и не является публичным отчётом.

Backup содержит историю, Telegram IDs, sessions и тела исходящих сообщений, поэтому нуждается в ограничении доступа. Встроенного шифрования и offsite backup нет. Не сохраняйте его в репозитории даже приватном.

Скриншоты показывают UI и учебные данные. Не захватывайте `.env`, BotFather token, request headers, окно ввода пароля, raw SQLite или список серверных ключей. PNG из artifacts — настоящие снимки приложения; скриншоты Telegram-клиента не заменяются макетами.

## Checklist перед передачей

- [ ] Перед публичной публикацией проверены исходники, артефакты и достижимая история; секреты и рабочие данные остаются вне Git. Репозиторий опубликован по прямому запросу владельца 30.09.2026.
- [ ] Рабочие/staged файлы и Git-история проверены; `.env` и БД не tracked.
- [ ] .env.example содержит только безопасные значения, реальные секреты передаются отдельно.
- [ ] HTTPS валиден без отключения проверки; admin без credentials закрыт.
- [ ] Нет публичного доступа к SQLite/.env/.git/backup.
- [ ] Webhook secret, allowlist, role/code и ownership проверены.
- [ ] Повтор update не меняет бизнес-состояние; failed/uncertain не переотправляются вслепую.
- [ ] Скриншоты и отчёты не содержат credentials/чувствительных данных.
- [ ] Существует проверенный приватный backup; оператор знает ограничения restore.
- [ ] Известные ограничения и фактически непроверенные сценарии указаны в TEST_RESULTS.

Этот checklist — действия перед конкретной передачей, не автоматически выполненные отметки. Результаты последней проверки и dependency audit — [TEST_RESULTS.md](TEST_RESULTS.md).
