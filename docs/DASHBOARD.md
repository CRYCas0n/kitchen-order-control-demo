# Дашборд руководителя

Над доской размещены шесть KPI, распределение по десяти этапам, состояние сроков, экономика и пять заказов, требующих внимания. Графики сделаны средствами HTML/CSS без зависимостей.

`GET /api/dashboard` возвращает `summary` вместе с заказами из одной читающей транзакции SQLite. `app/calculations.py:summarize_orders` агрегирует готовые признаки и экономику `enrich`, используемые карточками. Новых таблиц и сохранённых аналитических итогов нет. JS только отображает результат. Учебный снимок и сценарий имитации экспортируются тем же Python-кодом.

Правила:

- KPI охватывают все заказы и могут пересекаться. Клик сбрасывает остальные фильтры доски и включает выбранный признак; повторный клик снимает его. Общая сводка остаётся по всем заказам.
- Диаграмма сроков не пересекается: завершён с опозданием → активная просрочка → риск → в срок. Завершённые вовремя входят в «В срок». Просрочка и риск определяются существующими правилами относительно учебной даты 30.09.2026.
- Выручка и маржинальный доход суммируются только по заказам с полными фактическими данными. Средняя маржинальность — арифметическое среднее рассчитанных процентов, не отношение общих сумм. Рядом показано число включённых заказов.
- `NULL` не заменяется нулём. Когда подходящих заказов нет, сумма не отображается как ноль. При подтверждённой нулевой выручке процент не рассчитывается; если убытка нет, такой заказ показан отдельной строкой «Не рассчитывается: выручка 0». Убыток определяется по отрицательному доходу даже при нулевой выручке.
- Низкая маржинальность — менее существующего порога 15%. В распределении отрицательные и низкие значения разделены; KPI объединяет их.
- Внимание: сначала просроченные с открытой проблемой, затем прочие проблемные/просроченные, затем оставшиеся риски и неполные данные. Внутри группы — ближайший срок следующего действия, затем ID. Показаны максимум пять заказов; номер открывает карточку.
- Обновление API заменяет одновременно карточки и графики. Ошибка HTTP, сети или структуры сводки сохраняет предыдущие данные и время, показывая предупреждение об устаревании.

Проверка: 31 unittest, браузерный сценарий `scripts.browser_check` с временной SQLite и `scripts.dashboard_check` для публичного сайта без изменения данных. Локальный браузер проверяет точные наборы ID всех шести KPI, пересчёт после изменения стадии/прогноза/переделки, ошибку сети и некорректный HTTP 200, а также мобильную ширину 390 px. Результаты и снимки: `artifacts/browser-results.json`, `artifacts/dashboard-public-results.json`, изображения 30–33.
